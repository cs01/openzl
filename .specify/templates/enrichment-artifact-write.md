# Enrichment Artifact Write

Write reviewed enrichment findings to project artifacts: `project-context.md` prose, `scan-profile.json` projection, `enrichment.json` marker.

This file is read and executed by a subagent dispatched from `/speckit-setup` step 4, after the review gate (4-B) and rejection handling (4-C) resolve. It is NOT a standalone command.

## Inputs

The dispatching agent passes these via the Agent prompt:
- `ENVELOPES`: JSON array of all four dimension envelopes, post-review. Rejected dimensions (whole-dimension or all-findings-struck) have `status: "gap"` and `gap_reason: "user_rejected"`. Accepted dimensions keep their original `prose_markdown` and `machine` fields, with any individually struck findings removed from `prose_markdown`.
- `REFRESH_MODE`: `true` if this is an S2 refresh, `false` otherwise

## Write Artifacts

**Write ordering**: `project-context.md` prose FIRST, `scan-profile.json` projection SECOND, `enrichment.json` marker LAST (marker-last crash consistency).

**1. Compose prose**: Concatenate `prose_markdown` from envelopes that are NOT `user_rejected` under one reserved heading in `project-context.md`:

```markdown
## Deep Research Enrichment

<!-- Generated by /speckit-setup enrichment. Do not add framework headings here. -->

<prose_markdown from accepted architecture dimension>

<prose_markdown from accepted dependencies dimension>

<prose_markdown from accepted operational dimension>

<prose_markdown from accepted data_flow dimension>
```

**Idempotent replace**: If `## Deep Research Enrichment` already exists, delete the entire section (from `##` to next `##` or EOF) before writing. Never append duplicate sections.

If every dimension is `user_rejected`, omit the `## Deep Research Enrichment` section entirely (delete it if present; write nothing new).

**2. Merge machine findings**: Write findings JSON to temp file, then merge into project artifacts. Do not surface the script filename or internal tooling names in user-facing output — describe the operation as "Merging enrichment findings into project context" instead:

```bash
cat > /tmp/enrichment-findings-$$.json <<'EOF'
{
  "architecture": {"status": <arch_envelope.status>, "machine": <arch_envelope.machine>},
  "dependencies": {"status": <deps_envelope.status>, "machine": <deps_envelope.machine.dependencies>},
  "configuration": {"status": <deps_envelope.status>, "machine": <deps_envelope.machine.configuration>},
  "operational": {"status": <ops_envelope.status>, "machine": <ops_envelope.machine>},
  "data_flow": {"status": <df_envelope.status>, "machine": <df_envelope.machine>}
}
EOF

if [ "$REFRESH_MODE" = "true" ]; then
  speckit run enrichment-merge.sh persist --preserve-failed \
    .specify/memory/scan-profile.json \
    .specify/memory/enrichment.json \
    /tmp/enrichment-findings-$$.json 2>/tmp/enrichment-merge-$$.err
else
  speckit run enrichment-merge.sh persist \
    .specify/memory/scan-profile.json \
    .specify/memory/enrichment.json \
    /tmp/enrichment-findings-$$.json 2>/tmp/enrichment-merge-$$.err
fi
merge_exit=$?

if [ "$merge_exit" -eq 0 ]; then
  rm -f /tmp/enrichment-findings-$$.json /tmp/enrichment-merge-$$.err
fi
```

Capture `merge_exit` immediately after the `if`/`else` block — the trailing cleanup must not run unconditionally beforehand, or its own (successful) exit status overwrites the merge command's.

**3. Merge failure handling**: If `merge_exit` is non-zero:
- Roll back: Delete the prose section written in step 1
- Log actionable error: "⚠ Failed to merge enrichment findings. Details in `/tmp/enrichment-merge-$$.err`. Check `.specify/memory/` permissions and re-run `/speckit-setup` to retry."
- Leave `/tmp/enrichment-findings-$$.json` and `/tmp/enrichment-merge-$$.err` in place for inspection (not deleted on failure)
- Emit terminal status `failed` and stop

**4. Success**: If the merge exits zero, emit terminal status `ok`.

## Terminal Status

Every exit path — success or failure — MUST end the response with this line, and nothing after it:

```
enrichment_write_status: <ok|failed>
```
